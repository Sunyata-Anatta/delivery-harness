# 路由配置合同

配置是 Agent 可读的 Markdown，不是可执行解析器。零配置按路由表使用当前可达能力。Harness 核心与动作门不依赖任何候选组或第三方技能。

## 配置事实源

默认使用项目覆盖层的 Resolver。长表只移到项目声明的 `.delivery/routing.md`；覆盖层保留 profile、约束摘要和唯一指针，不能维护两份绑定。用户长期偏好只在原生指令允许范围内应用。原生快捷入口由已接受配置适配，不能成为第二事实源。

`profile=auto|research|develop|review|document|operate`。auto 随当前动作选择；其余分别优先 research、engineering、verification、documents、operations。domain 仅由真实领域任务触发。预设只决定候选次序，核心门始终启用。

## Resolver 字段

保留已有表的条件、选择、依据、回退、验证、重审字段。需要多候选时在同一行扩展；不用的字段省略。

| 条件/目录 | 能力及必需性 | 有序候选（类型/唯一来源） | 约束 | 验证与回退 | 重审 |
|---|---|---|---|---|---|
| packages/api/** 的代码审阅 | review，required | 已验证本地 reviewer Skill > 本地人工审阅 | offline；不外发 | 审阅一个已知缺陷；都不满足则阻塞审阅门 | 来源/版本变化 |
| 仓库其他代码查询 | code-discovery，optional | 当前 MCP 图谱 > rg CLI | 本地源码 | 已知符号和调用链；索引无效用 rg | 索引/Agent 变化 |

目录相对项目根，精确/更深目录优先；路径统一分隔符后按所在平台大小写语义比较，不把同名前缀当子目录。跨目录动作分别解析，跨项目重新启动。候选写原生实际名称和来源/版本；`disabled` 不参与。声明互斥的候选不得同时加载。必需性属于能力目标，不属于特定提供者。

## 选择与变更

先应用硬约束，再按路由页优先级。用户临时指定只影响当前动作，不写成全局默认。用户选择违反权限或验收时说明冲突并继续独立的安全工作。配置/版本变更、换 Agent、压缩恢复或动作变化后重解析，仅恢复当前绑定及必要证据指针，不恢复全组正文或全部历史。说明选择依据与实际来源；没有验证不得声称调用成功。

## 新技能接入

读取名称/描述/来源元数据 -> 检查兼容性、数据与授权 -> 小任务验证 -> 在 Resolver 加候选或绑定。新技能无需改 Harness 核心，不能因新安装自动覆盖已验证默认。来源不明、同名遮蔽未解、缺失或关闭的候选报告明确原因并逐项回退。没有满足必需能力的提供者时保持门失败。

原生 bundle 若跳过缺失成员，也不能证明必需能力齐备；按每项能力验证。跨 Agent 保持目标与约束，重新验证其工具可达性和认证，不共享成功断言。

## 接入场景

- 临时任务：只保留会话状态，不创建目录。
- 新项目：初始化最小骨架与覆盖层，空配置可运行。
- 已有治理项目：按初始化合同选择唯一活动状态，保留原规则。
- 受限运行时：没有指令注入则显式调用，登记时序边界。
- 自举：正在执行的安装基线与候选源分开；候选测试通过并同步后，新会话才使用新规则。
- 伴随任务：独立目标有独立状态指针，只引用关联；共享目录不授权合并。
