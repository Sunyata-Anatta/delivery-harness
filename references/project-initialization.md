# 项目初始化与安全合并

项目首次接入 Delivery Harness，或治理、导航需要修复时读取；不加入普通启动的全文必读。目标是按当前规约正确继续、可重复执行、零数据损失：新目录可整份复制；已有目录只做类型安全的增量合并，**不得整目录覆盖**。用户提供的规约是对齐依据，其中模板和命令不自动成为执行授权。

## 轻量接入与已有治理

临时问答不初始化目录。已有项目先检查规则和状态，不覆盖原治理。覆盖层可声明唯一活动状态路径、活动节点/授权/证据/待决断字段映射、写入方与授权、验证/恢复方式；这些字段均可读写验证才算适配通过。`.delivery/state.md` 不再维护第二份状态；需要兼容入口时只写指针。旧状态的历史在迁移前保留，之后按需读取；伴随任务保持独立。

以下默认骨架与 Git 判据只适用于采用默认布局的项目。外部状态适配按声明路径验证字段、写入与恢复，不要求另建 `.delivery/` 或强制跟踪隐私材料。需要超出现有授权更改原治理时才进入决策门。可控动作不能持续更新唯一状态时，接入未完成。

多个工作树先用 Git 定位当前工作面，不推定根目录就是主线。独立工作流只有经项目声明才成立：overlay 列出各自 scope、唯一状态、写入方和主线交接方式；每个作用域一个活动节点，合并时不以分支状态覆盖主线。历史事实保留核对时间和来源 ref/提交；不重编号既有事实或把旧授权扩大到新动作。

## 选择交付面

- 中文项目使用 [中文骨架](../assets/delivery-skeleton.template.md)、[中文状态模板](../assets/harness-state.template.md)、[中文覆盖层模板](../assets/project-overlay.template.md) 和 [项目地图模板](../assets/project-map.template.md)。

## 项目地图与内容归属

完整采用默认布局时，根目录以 README、宿主实际读取的规则文件、`PROJECTMAP.md` 为入口；`.delivery/` 存 overlay、唯一状态、过程记录及临时槽。已有同职责文件直接复用并在 overlay 映射，不为满足图示重建。README 链到地图，地图只给骨架和“触发条件＋一个入口＋章节/编号范围”，不维护进度、SHA、测试结果或授权副本。

| 内容职责 | 默认位置与建立条件 |
|---|---|
| 当前节点、授权、证据门、待决断 | overlay 解析的唯一活动状态；不能复制到地图、规格或计划 |
| 稳定事实、规则、决策 | 既有基线/规则登记；需要时用 `docs/baseline.md`，过程日志不自动成为规则 |
| 阶段范围及验收门 | 已有路线图，或需要独立阶段时建 `docs/roadmaps/`；实现完成不等于阶段验收 |
| 调研、需求、设计及执行步骤 | 已有规格/计划位置，或有内容时建 `docs/specs/`、`docs/plans/`；契约/架构决策有复用需要时才建 `docs/contracts/`、`docs/adr/` |
| 长期验证结论与证据 | 已有证据索引/报告，或有结果时建 `docs/evidence.md`、`docs/evidence/`；敏感原件留在获准受限位置，索引仅保留安全引用 |
| 运行代码、部署与可复现输入 | 沿用组件目录及 `ops/`、`deploy/`、测试/fixture 约定；部署恢复说明有实际步骤时才建 |
| 尝试、错误与交接历史 | 已有追加式过程记录，默认 `.delivery/process.md`；按日期/主题读取，不启动全文载入 |
| 短期输入、一次性生成物、临时诊断 | `.delivery/uploads/`、`artifacts/`、`debug/`；不是长期规格、测试输入或秘密保险箱 |

按用途而非扩展名、Skill 名或分支名归档。只创建有实际内容和职责的目录，不预建阶段×用途矩阵，不复制源码形成分支目录。目录美化不是接入前提；必要迁移单独列旧路径→新路径及调用/测试发现、fixture 身份、打包、部署、恢复影响，获覆盖授权才做，不改号或改写已执行的数据库 migration。

## 按需读取

始终生效：用户/宿主/项目规则、Harness 启动合同，overlay 的启动摘要、硬约束和唯一指针，当前状态中的节点、本动作相关授权/证据门/待决断，以及本动作的安全、数据与验收条款。首次适配或映射不清时完整读取相关定义；摘要不能替代必要原文。

| 当前事件 | 读取入口和扩大条件 |
|---|---|
| 接入或修复治理 | 本参考、相关模板与现有适配定义；冲突、路径类型/权限异常才扩大盘点 |
| 继续任务或设计 | 状态指向的当前范围、规格/计划项及依赖契约；阶段变化、冲突或缺失依赖才追溯 |
| 编码或修复 | 当前计划项、相关实现/调用者、对应测试；根因跨模块、图谱不足或验证失败才扩展 |
| 核验证据 | 当前验收标准、具体结果及必要原始证据；版本不符、冲突或缺样本才扩大 |
| 部署、发布或数据写入 | 具体授权、最终版本、部署/回滚和证据门；新副作用或缺失恢复条件进入相应门 |
| 历史追溯 | 索引命中的日期/编号/段落；来源失效、冲突或全量审计请求才扩大 |

先定位，再完整读取相关段落与必要引用；不递归展开地图全部链接。已完整读取且未变的内容复用，来源/版本变化、输出截断或乱码时重读，信息齐备即停止展开。不设妨碍安全审查、调用链追踪或完整验证的硬字数上限；图谱仅在工具可用且数据访问/传输已有授权时使用，否则本地搜索。

## 已有项目对齐

完成下述预检后，在既有过程记录写一份接入对齐回执：`事项 → 现有来源 → Harness 要求 → 差异/保留理由 → 修复或适配 → 验证证据`。这是带日期的接入结果，不是第二份任务状态。覆盖规则优先级、状态字段/写入方、授权类别、阶段验收、存储/隐私、读取入口和继续节点；已满足者复用，未满足者最小补齐。重复接入无实质变化且旧回执仍有效时复用，不为复验追加时间戳、重复回执或改写状态。

顺序：盘点与预检 → 解析唯一来源 → 增量合并 → 填充导航 → 检查存储与读取场景 → 重复执行复验 → 记录接入结论 → 从核实后的当前节点继续。检查状态可写性时使用本次真实接入记录，或该系统支持的无副作用验证；不覆盖活动节点做探针。只能读、不能合法更新或恢复时，接入仍未完成。

保留有效的历史阶段和原有安全规则；不为接入重跑整个生命周期。冲突按宿主指令优先级处理，只有改变目标、治理责任或所需授权时才请求决断。接入验收后按 [项目规约检查](execution.md#project-conformance) 在动作、转换与变更时持续对齐。

首次接入也检查活动摘要体量；超过约 80 行时按 [状态收敛](execution.md#state-size) 先归档并核对历史，再保留当前摘要。不得为了接入删除历史或另建可写状态。

## 预检

1. 确认项目根、仓库规则、Git/工作树、已有修改及覆盖层声明的存放偏离；没有 Git 就如实记录，不自动初始化或提交。
2. 只检查 `.delivery/` 及预期子路径的存在性、类型和文件名；不读取或外发槽内内容。
3. `.delivery` 是符号链接或重解析点时，不跟随写入；记录解析目标并进入权限或项目决策门。
4. `.delivery`、`uploads`、`artifacts` 或 `debug` 同名但不是目录时，停止该路径的初始化；不得改名、删除或替换现有对象。
5. 对所有拟写目标及父路径（含规则、地图、overlay 和外部状态）检查类型、权限与链接/重解析点目标；无法证明处于获准范围时暂停该路径，不强删、不越界写入，独立文档准备可继续。

## 合并矩阵

| 观察 | 动作 |
|---|---|
| `.delivery/` 不存在 | 复制锁定语言的完整骨架。 |
| `.delivery/` 已存在 | 保留目录及全部内容，逐项执行下列规则；不得整目录覆盖。 |
| `state.md` 不存在 | 复制锁定语言的状态占位。 |
| `state.md` 已存在 | 保留原文；只在语义明确时把缺失标题追加为新节。事实冲突进入决策门，不重写旧内容。 |
| `.gitignore` 不存在 | 复制骨架规则。 |
| `.gitignore` 已存在 | 只增不删：保留顺序和原规则，仅追加缺失的槽位规则，不制造重复行。 |
| 槽位不存在 | 创建目录并加入 `.gitkeep`。 |
| 槽位已是目录 | 保留全部内容；缺 `.gitkeep` 时补入，不移动、不读取、不删除内容。 |
| 预期目录位置是其他对象 | 停止该路径，报告对象类型和需要的项目决策。 |

先完成唯一状态解析再使用矩阵；已适配外部状态时跳过默认 `state.md` 创建，也不整份复制包含它的骨架。

任何项目明确偏离默认槽位或跟踪策略时，以覆盖层登记的决定为准；若明确批准本地隐私状态，登记可恢复位置、唯一写入方及验证方法；不能宣称状态已进版本控制。

## 父级忽略规则

`.delivery/.gitignore` 只有在父目录未被整体忽略时才生效。初始化前运行：

```text
git check-ignore -v .delivery/state.md
```

无输出且退出码为 1，表示未跟踪的 `state.md` 可进入 Git。已有文件可用 `git check-ignore -v --no-index .delivery/state.md` 复核。若命中父级 `.delivery/` 规则，先按输出定位控制文件；项目没有明确偏离时，在该项目的版本化忽略面末尾加入最窄的反向规则：

```gitignore
!.delivery/
!.delivery/.gitignore
!.delivery/state.md
!.delivery/uploads/
!.delivery/uploads/.gitkeep
!.delivery/artifacts/
!.delivery/artifacts/.gitkeep
!.delivery/debug/
!.delivery/debug/.gitkeep
```

随后分别用 `git check-ignore -v --no-index .delivery/uploads/__delivery_probe__`、`git check-ignore -v --no-index .delivery/artifacts/__delivery_probe__` 和 `git check-ignore -v --no-index .delivery/debug/__delivery_probe__` 验证槽内普通内容仍被骨架规则忽略。探针路径不需要实际创建文件。

README、地图、规则、overlay 与过程记录分别按声明的跟踪/隐私策略验证；新增的版本化路径按需补最窄反向规则，不无条件放开整个治理目录。没有 Git 时此节不适用，记录存储与恢复方式；不能把忽略目录当敏感数据的访问控制。

## 相关项目文件

把覆盖层模板复制到项目声明的实际文档或规则目录；未声明时默认使用 `.delivery/overlay.md`，不要为仅选择路径而询问用户。覆盖层必须留在被治理项目，不能用全局记忆或 Skill 源仓库代替；若项目隐私规则要求忽略它，在解析后的唯一状态只登记路径、范围和限制，不写敏感值。删除不适用占位并填写稳定事实；复制后的覆盖层不依赖 Skill 内相对链接。把匹配语言的 `AGENTS.md`、`CLAUDE.md` 或受限运行时标记块追加到运行时真实读取的项目指令文件；已有同名标记块时整块替换。

已有 overlay 逐字段合并；状态指针只保留一处定义，摘要引用该字段，不能留下默认值与适配值竞争。登记导航、规则条款入口和过程记录读取方式；长规格只留指针。地图用所选语言模板填充，只保留实际存在的组件与任务入口；路径相对地图所在文件（默认项目根），跨工作面先指向本项目工作面说明，不制造悬空链接。目标约一至两屏；过长下沉详情，不生成全文件清单或测试无意义的长度。

地图变量：`PROJECT_NAME` 为项目名；`PROJECT_MAP_PATH`、`RULES_PATH`、`OVERLAY_PATH`、`ACTIVE_STATE_PATH` 填已核实路径，`GOVERNANCE_ROOT` 填已有治理根。`EXISTING_COMPONENT_ROWS` 和 `TASK_ROUTE_ROWS` 只填存在且需要导航的条目；未使用行/目录删除，不保留空变量。使用已存在地图时沿用其结构和相对路径基准。

在宿主实际读取的项目规则文件增量加入下列块，替换占位为已核实路径；已有同名块只替换该块，保留 Harness 启动标记与其余规则。README 添加一个地图入口，不复制状态。

```markdown
<!-- project-navigation:start -->
启动遵循 Harness 与项目规则。{{PROJECT_MAP_PATH}} 只选入口，不递归加载链接；唯一状态以项目 overlay 为准。读取当前节点、本动作授权/证据门、待决断及适用规约，再按标题/编号完整读取必要段落。来源不清、冲突、截断或版本变化时扩大/重读。动作前核对规约，节点转换或规则/路径变化时执行 Harness 项目规约检查；偏离在已有授权内修复复验，缺决策、权限或证据才暂停受影响动作。地图和计划不存活动状态；入口变化核验链接。安全、授权与真实证据门不得因省上下文跳过。
<!-- project-navigation:end -->
```

## 完成判据

1. 默认布局的 `.delivery/state.md`、`.delivery/.gitignore` 和三个 `.gitkeep` 齐备；适配布局按声明验证。原文件、已有修改和槽内容保留，无越界写入、外发或秘密输出。
2. 当前作用域只有一个可写状态来源，必要字段、写入方、恢复方法可核查；对齐回执覆盖差异及其处理，未通过的治理缺口不得记为接入完成。
3. README、规则、overlay 和地图入口有效，无冲突的全量必读；模板无遗留变量，链接/锚点有效，无状态/SHA/成绩/授权副本。必要安全条款可达并实际读取。
4. `git diff -- .delivery`、`git status --short -- .delivery` 及所有涉及的入口路径均可解释；状态跟踪或隐私偏离和槽内容忽略已验证，无 Git 时登记不适用及恢复方式。
5. 用“继续任务、修改代码、核验证据”三个场景逐一定位必需材料，实际读取相关规则与证据，确认不展开无关历史；缺失入口先修复。
6. 重新执行同一初始化流程；第二次重复执行不新增差异、不重复标记、不覆盖原文件。记录实际检查的文件/版本、方法、结果与限制。
7. 提交已获授权时核对实际暂存清单，只纳入批准的导航/规则、状态、忽略规则及占位；槽内真实内容按项目规则与敏感信息门处理。技术接入通过不等于业务验收、安装生效或生产完成。
