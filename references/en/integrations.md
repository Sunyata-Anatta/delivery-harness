# External Integrations

Delivery Harness may guide Git hosting, databases, deployment platforms, knowledge systems, and other tools only when the active node needs them. Optional services are not general dependencies.

## What may proceed

- Inspect exposed connectors, CLIs, project configuration, and read-only state.
- Check whether a required action exists and whether that client is authenticated.
- Use primary documentation for installation, login, scopes, and verification.
- Complete reversible project-level configuration within existing authority.
- Recheck capability and resume the failed node.

Global plugins, skills, hooks, trusted programs, account authentication, paid services, project-data transfer, browser login state, broader permissions, organization changes, and persistent machine configuration require explicit authority.

Select the smallest capable route: existing local capability, authorized connector, independently authenticated CLI, then browser interaction only after permission. These authentication states are separate facts.

Before declaring a block, report attempted capability/action, exact result or error, confirmed connection/capability/authentication state, sole remaining block, and complete recovery path. Record integration purpose, client type, non-secret owner, scopes, source/version, verification, data boundary, cost, rollback, and revisit condition in the project overlay.
