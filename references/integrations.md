# 外部集成

Delivery Harness 可以引导项目配置 GitHub、数据库、部署平台、知识库或其他外部工具，但只在当前节点确实需要时介入。它负责发现、说明、验证和继续执行，不负责悄悄扩大权限。

## 默认决定

不把 GitHub 设为硬依赖，也不把任何可选服务写进通用 Agent 配置。这样，本地项目、离线项目和使用其他托管平台的项目都能运行同一技能。

只有核心流程离开某个连接器就无法工作时，才把它声明为硬依赖。项目只是选择使用某个服务时，把配置和授权状态记在项目覆盖层。

## 自动引导的范围

Harness 可以自动执行：

- 查看当前暴露的连接器、CLI、项目配置和只读状态；
- 检查某个动作是否存在，以及当前客户端是否已认证；
- 从官方资料给出安装、登录、权限范围和验证步骤；
- 在既有授权范围内完成可逆的项目级配置；
- 配置完成后复核能力并从原失败节点继续。

Harness 不得静默安装全局插件、Skill、Hook 或受信任程序，不得静默认证账号。它也不得索取或回显秘密、启用付费服务、扩大权限范围、使用浏览器登录态、改变组织设置，或修改持久机器配置，除非用户已明确授权该动作。

## 选择能力

按以下顺序选择能完成任务的最小能力：

1. 项目已经具备的本地能力。
2. 已安装且已授权的专用连接器。
3. 已安装并独立认证的 CLI。
4. 经用户明确允许后使用浏览器交互。

连接器已连接、CLI 已登录、浏览器已登录是三个不同事实。一个状态不能证明另一个状态。

## 受阻时的输出

先实际尝试允许的检查，再报告：

```text
已尝试：<能力和具体动作>
结果：<成功、错误码、缺少动作或缺少权限>
已确认：<连接、能力和认证分别处于什么状态>
阻塞：<唯一剩余阻塞>
下一步：<完整配置或恢复流程，以及需要用户完成的动作>
```

如果安装或认证必须由用户完成，给出从安装到最终验证的完整路径。不要只给一条命令，也不要把未尝试写成不可用。

## 项目记录

在项目覆盖层记录：

- 集成名称和用途；
- 使用连接器、CLI 还是浏览器；
- 账号或资源所有者，不记录秘密；
- 已授予的能力和范围；
- 配置来源、版本和验证命令；
- 数据是否离开本机或组织边界；
- 费用、回滚方式和重审条件。

GitHub 的认证、建库、远端绑定、推送和私有仓库权限判断见 [github.md](github.md)。
