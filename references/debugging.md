# 自主排错与恢复

当节点失败、命令异常、结果冲突或验证不通过时读取本文件。目标是在既有授权内恢复推进，减少不必要的人工干预。

## 固定流程

```text
失败 -> 复现 -> 分类 -> 安全诊断 -> 恢复 -> 复验 -> 继续
```

1. 复现原动作，保留命令、退出码、错误类别和最小相关上下文。不要根据单次失败猜测根因。
2. 分类为实现缺陷、测试或数据错误、环境差异、执行上下文隔离、网络、权限或凭据、工具能力缺口、真实证据缺失，或用户决策缺失。
3. 先执行不改变状态的诊断。读取本机、项目、运行时和客户端事实，确认调用的是哪个账号、凭据存储、网络、服务或工具。
4. 在既有授权内选择最小恢复动作：修复实现、重跑可靠命令、使用等价的已授权执行上下文、使用已安装的替代客户端，或回退可逆的项目级改动。
5. 恢复后必须重新执行原失败动作，并运行与风险相称的完整验证。只有复验通过，才回到原节点继续。

## 执行上下文隔离

沙箱、桌面会话、CI、容器、CLI、连接器和浏览器可能拥有不同的网络、文件、凭据库和登录态。一个上下文中的 401、无凭据或不可访问，不能单独证明账号、令牌或服务本身失效。

当失败涉及认证、网络或工具可见性时：

1. 记录失败上下文和准确错误。
2. 在不使用浏览器登录态、不安装软件、不修改持久配置的前提下，检查等价且已授权的上下文。
3. 比较账号、权限、目标资源和命令结果。
4. 仅在所有允许的上下文都失败时，才判定为真实认证、权限或服务阻塞。

不得把可由代理安全诊断或恢复的问题过早转交给用户。不得通过静默登录、安装、扩大权限、使用付费服务、破坏性操作或推测性改动来绕过失败。

## 停止条件

仅在以下情况暂停并向用户报告：

- 需要目标、范围、架构或验收标准的实质决策；
- 恢复需要新的登录、凭据、权限、持久配置、付费服务、浏览器登录态或外部协调；
- 恢复涉及不可逆的文件、数据、历史、基础设施或生产操作；
- 必需的真实样本、账号、设备、服务或验收证据不存在；
- 已穷尽既有授权内的诊断与安全恢复路径。

报告必须说明已尝试动作、证据、确认的根因、已排除路径、唯一剩余阻塞和解除条件。不要让用户重复已经由代理完成的检查。
