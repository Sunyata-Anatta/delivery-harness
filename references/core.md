# 执行核心

只维持一个活动节点；简单问答不创建项目状态。先遵守已注入的启动块；显式冷调用仅允许先读 Skill 与本核心，再回执、再业务工具，不能计为预注入通过。回执列规则、版本控制、节点、边界、当前能力信号；未知写待探测，随后只读核实。

冷调用也使用下列固定块；已知项替换待探测，保留字段名称。与任务无关的探测写不适用及理由。

```text
【启动回执】
规则：待探测
版本控制：待探测
节点：待探测
边界：待探测
【能力信号评估】当前触发项或无；理由。
```

项目启动只读项目规则、覆盖层（默认 `.delivery/overlay.md`）、唯一活动状态（默认 `.delivery/state.md`）及当前 Git/环境事实；旧回执复用前重新探测。已有治理状态可由覆盖层声明唯一指针，禁止双写；接入见 [初始化](project-initialization.md)。新证据先登记时间、来源或 `needs-source`、观察与限制；事实不等于授权。

每个动作前按触发读一项：

| 事件 | 必读 |
|---|---|
| 新节点、状态转换、TDD、长测试、项目完成 | [执行](execution.md) |
| 决策、权限、新证据、暂存/提交、部署/发布、最终审阅 | [门控](gates.md) |
| 专业能力选择或变化 | [路由](capability-routing.md) |
| 安装、预注入、更新或回滚 | [运行时](runtime-installation.md) |
| 失败/重试 | [排错](debugging.md)、必要时[原则](principles.md) |
| 委派；外部服务；GitHub | [Agent](agent-config.md)；[集成](integrations.md)；[GitHub](github.md) |

授权按动作类别核对，已有授权覆盖就继续；条件检查不授权实施。回执不能代替原始证据。全局变更、外发、付费和发布核对明确授权。值不进上下文，诊断默认不落盘、归档先脱敏。禁止以测试代替真实证据，以旧审阅覆盖新产物，或把失败/额度不足称为完成。未获授权不委派。门通过后更新状态与相关文档并继续；必要工作未完只因真实决策、权限或证据阻塞暂停，写明解除条件。
