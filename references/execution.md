# 节点执行参考

按活动节点只读对应小节。通用阶段、状态转换和停止规则仍在 `SKILL.md`。

## reality_audit：从现实开始

读取仓库规则、项目覆盖层、`.delivery/state.md`、已接受规格与计划、相关实现和测试、Git 状态及可用运行证据。区分已设计、实现、测试、部署和验收；明确目标、非目标、成功证据、约束、风险、授权边界、活动节点及下一门。旧消息、路线图勾选和模拟结果不能单独证明当前实现。

收到截图、原件、人工决定或外部结果时，先写最小证据回执，再分析或提出设计：记录接收时间、可复核来源（否则 `needs-source`）、范围、直接观察、限制和未决。该回执只冻结事实，不表示已经批准方案，也不授权副作用。

新会话或新活动节点复用旧证据前，检查既有回执是否含 `source_ref` 或 `needs-source`；缺失时先补录，不能直接作为实施、部署或外部写入依据。

项目需要本地规则、长期经验或 Resolver 时使用 [项目覆盖层模板](../assets/project-overlay.template.md)。覆盖层保存稳定项目事实；`state.md` 保存易变活动状态。

## requirements：厘清需求

确认用户结果、角色、敏感数据、隐私与权限、输入输出、规模、延迟、准确率、可靠性、离线、代表性样本、兼容性、部署、回滚，以及可逆 MVP 边界。一次只问一个真正阻塞的问题；安全假设不改变行为或风险时记录后继续。

## tool_research：调研当前工具

当库、模型、服务、Skill、协议、许可证或部署选项可能变化时，先查项目既有决定，再用一手资料核对版本、平台、许可证、安全、遥测、维护和部署要求。至少比较零新增基线、当前已有能力和需求足以证明合理的最强替代方案。

记录证据日期，区分事实与推断。自造分类、匹配、评分、相似度或阈值方法前先查成熟方案与公开基准；现成方案与自造方案都用同一批真实样本验证。只读联网研究可直接进行；安装、付费、外发数据和扩大权限另过授权门。

## solution_decision / design_and_plan：决策与计划

仅当选项实质改变行为、架构、持久数据、隐私、成本、许可证、部署风险或长期运行方式时请求用户决断。普通可逆细节采用满足验收的最简单方案。

记录选择、理由、淘汰方案、假设、风险、回滚和重审条件。实施节点写明文件、RED 测试、目标、验证命令、依赖、估时和停止门。强规则必须锚定外部可观测事件，写全触发、动作、执行方法、判据、失败处理和证据；升级条件使用可观测事件计数。

把证据登记、可逆本地实验、远端部署、外部持久写入以及导入/激活列为不同动作类别。用户说“先检查并反馈”时，先交付检查结果；该条件性授权不覆盖实现或副作用。预实验单列目的、未覆盖验收、回滚与禁止推导结论，不能用“已部署”代替已批准设计的实现证据。

## environment_and_authority：环境与授权

先做只读检查，记录系统、运行时、依赖、网络、存储、服务、凭据边界、仓库结构、无关改动和验证命令。优先复用现有组件；第三方软件先查来源、许可证、遥测、安装脚本和安全影响。

授权请求说明动作、目标、持久性、外部影响和回滚。预授权工具集只免除集合内逐次询问，不免除适配检查、安装后验证和登记。

本地 RED/GREEN 或已写出的计划不自动授权远端复制、服务重启、外部持久数据写入、导入或激活。任何此类副作用均按其自身动作类别核对明确授权；模糊或条件性措辞按未获授权处理。

## repository_integration：集成仓库

- 保留无关改动，只增加目标所需内容；验证安装与回滚。
- 不提交秘密、个人信息或机器专属路径。可能接触凭据的命令先遮蔽值，**值不进上下文**；诊断结果**默认不落盘**，归档前脱敏。已泄露时不重复值，登记轮换、残留清理和暴露面。
- 输入输出目录派生自项目根或证据槽；绝对路径由参数注入并在覆盖层登记。
- 提交前读取实际暂存清单，提交说明覆盖全部文件；运行秘密扫描、通用性检查和身份检查。
- 交付路径与仅开发路径分开；交付物依赖按交付边界判断。缓存和索引默认可重建。

## tdd_nodes：逐节点 TDD

对每个行为执行：写最小测试；确认预期 RED；做最小实现；确认聚焦 GREEN；仅在 GREEN 后重构；按风险跑回归与真实产物；修根因而不削弱测试；提交前同步状态和对照文档；获授权时提交并激活下一节点。

## real_evidence：验证真实证据

完成声明前执行 `IDENTIFY -> RUN -> READ -> VERIFY -> THEN`，记录命令、退出码、测试数、产物或观察和限制。单元测试不能替代需求指定的真实样本、设备、浏览器、数据集、账号、外部服务、类生产负载或用户验收。

独立审阅发现 Critical/Important 问题时，把问题设为活动节点，复现、最小修复并重审；除非确有新决策、权限或证据阻塞，否则不得在该发现处结束本轮。不能继续时按门控写出停止理由和解除条件。

启动长测试、独立审阅或门控动作前，先保留足以读取结果、更新状态和启动下一门的运行余量。余量不足或不可确认时，先写可恢复交接：活动发现/证据、已完成验证、冻结的副作用、唯一恢复动作和解除条件；额度耗尽后不得视为完成，下一会话先恢复并重审。

证据产物登记位置、可达方式、处理过程、结论、边界和复核日期。默认槽：`.delivery/uploads/`、`artifacts/`、`debug/`。声明证据缺失前，先说明当前机器、目录、网络和权限的可达边界，不把不可达当成不存在。
