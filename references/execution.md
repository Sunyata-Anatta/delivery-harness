# 节点执行参考

先读本页末尾的公共合同，再读当前节点小节；普通启动只读 [核心](core.md)。

## reality_audit：从现实开始

读取仓库规则、覆盖层启动摘要及其解析的唯一活动状态、Git 状态；用项目地图定位当前节点所需的规格、计划、实现、测试和运行证据，按章节/编号读取，不把链接清单当全文必读。区分已设计、实现、测试、部署和验收；明确目标、非目标、成功证据、约束、风险、授权边界、活动节点及下一门。旧消息、路线图勾选和模拟结果不能单独证明当前实现。

收到截图、原件、人工决定或外部结果时，先写最小证据回执，再分析或提出设计：记录接收时间、可复核来源（否则 `needs-source`）、范围、直接观察、限制和未决。该回执只冻结事实，不表示已经批准方案，也不授权副作用。

新会话或新活动节点复用旧证据前，检查既有回执是否含 `source_ref` 或 `needs-source`；缺失时先补录，不能直接作为实施、部署或外部写入依据。

项目需要本地规则、长期经验或 Resolver 时使用 [项目覆盖层模板](../assets/project-overlay.template.md)。覆盖层保存稳定项目事实；唯一活动状态保存易变内容。首次接入或治理缺口按 [初始化](project-initialization.md) 做现状映射与对齐，不从头重跑已完成阶段。

## requirements：厘清需求

确认用户结果、角色、敏感数据、隐私与权限、输入输出、规模、延迟、准确率、可靠性、离线、代表性样本、兼容性、部署、回滚，以及可逆 MVP 边界。一次只问一个真正阻塞的问题；安全假设不改变行为或风险时记录后继续。

## tool_research：调研当前工具

当库、模型、服务、Skill、协议、许可证或部署选项可能变化时，先查项目既有决定，再用一手资料核对版本、平台、许可证、安全、遥测、维护和部署要求。至少比较零新增基线、当前已有能力和需求足以证明合理的最强替代方案。

记录证据日期，区分事实与推断。自造分类、匹配、评分、相似度或阈值方法前先查成熟方案与公开基准；现成方案与自造方案都用同一批真实样本验证。只读联网研究可直接进行；安装、付费、外发数据和扩大权限另过授权门。

## solution_decision / design_and_plan：决策与计划

仅当选项实质改变行为、架构、持久数据、隐私、成本、许可证、部署风险或长期运行方式时请求用户决断。普通可逆细节采用满足验收的最简单方案。

记录选择、理由、淘汰方案、假设、风险、回滚和重审条件。实施节点写明文件、RED 测试、目标、验证命令、依赖、估时和停止门。强规则必须锚定外部可观测事件，写全触发、动作、执行方法、判据、失败处理和证据；升级条件使用可观测事件计数。

把证据登记、可逆本地实验、远端部署、外部持久写入以及导入/激活列为不同动作类别。用户说“先检查并反馈”时，先交付检查结果；该条件性授权不覆盖实现或副作用。预实验单列目的、未覆盖验收、回滚与禁止推导结论，不能用“已部署”代替已批准设计的实现证据。

## environment_and_authority：环境与授权

先做只读检查，记录系统、运行时、依赖、网络、存储、服务、凭据边界、仓库结构、无关改动和验证命令。优先复用现有组件；第三方软件先查来源、许可证、遥测、安装脚本和安全影响。

授权请求说明动作、目标、持久性、外部影响和回滚。预授权工具集只免除集合内逐次询问，不免除适配检查、安装后验证和登记。

本地 RED/GREEN 或已写出的计划不自动授权远端复制、服务重启、外部持久数据写入、导入或激活。任何此类副作用均按其自身动作类别核对明确授权；模糊或条件性措辞按未获授权处理。

## repository_integration：集成仓库

- 保留无关改动，只增加目标所需内容；验证安装与回滚。
- 不提交秘密、个人信息或机器专属路径。可能接触凭据的命令先遮蔽值，**值不进上下文**；诊断结果**默认不落盘**，归档前脱敏。已泄露时不重复值，登记轮换、残留清理和暴露面。
- 输入输出目录派生自项目根或证据槽；绝对路径由参数注入并在覆盖层登记。
- 提交前读取实际暂存清单，提交说明覆盖全部文件；运行秘密扫描、通用性检查和身份检查。
- 交付路径与仅开发路径分开；交付物依赖按交付边界判断。缓存和索引默认可重建。

## tdd_nodes：逐节点 TDD

对每个行为执行：写最小测试；确认预期 RED；做最小实现；确认聚焦 GREEN；仅在 GREEN 后重构；按风险跑回归与真实产物；修根因而不削弱测试；提交前同步状态和对照文档；获授权时提交并激活下一节点。

## real_evidence：验证真实证据

完成声明前执行 `IDENTIFY -> RUN -> READ -> VERIFY -> THEN`，记录命令、退出码、测试数、产物或观察和限制。单元测试不能替代需求指定的真实样本、设备、浏览器、数据集、账号、外部服务、类生产负载或用户验收。

独立审阅发现 Critical/Important 问题时，把问题设为活动节点，复现、最小修复并重审；除非确有新决策、权限或证据阻塞，否则不得在该发现处结束本轮。不能继续时按门控写出停止理由和解除条件。

最后一次独立审阅后的代码、运行配置或交付包变更会使旧审阅失效；部署、发布或完成声明前必须审阅最终产物，测试、扫描、自审和旧版本现场验证不能替代。

证据产物登记位置、可达方式、处理过程、结论、边界和复核日期。默认槽：`.delivery/uploads/`、`artifacts/`、`debug/`。声明证据缺失前，先说明当前机器、目录、网络和权限的可达边界，不把不可达当成不存在。

## 公共合同：状态与转换


默认存放根是 `.delivery/`。`state.md` 是活动状态的唯一事实源；采用既有治理时，每次读写先解析覆盖层的唯一指针，不再写默认路径。默认进入版本控制，明确的隐私偏离或已有治理状态适配按项目初始化合同登记；只写活动节点、当次授权、已过证据门和待决断。稳定项目事实、命令、规则、Resolver 和经验写项目覆盖层；仓库未声明其他规则文档路径时，默认使用 `.delivery/overlay.md`，不得把全局记忆或 Skill 源仓库当作其替代。若项目隐私规则要求忽略该覆盖层，在唯一状态只登记其路径、范围和限制，不写敏感值。`uploads/`、`artifacts/`、`debug/` 是默认忽略的临时槽，不随交付分发；长期规格、证据和可复现输入按 [内容归属](project-initialization.md#project-map) 存放。只有采用默认布局的首次接入才复制完整的 [`.delivery` 骨架](../assets/delivery-skeleton.template.md)；项目可在覆盖层改存放根并登记偏离。

分支、HEAD、工作树、远端、身份、安装清单等**可现查事实**不得作为无时限的当前断言。需要登记时写成证据回执，包含验证时间、判据命令或解析器、适用范围和限制；后续会话引用前必须重新探测，事实漂移后立即更新活动状态。历史回执保留其 `as_of` 语义，不冒充当前现实。

<a id="state-size"></a>
### 状态收敛：约 80 行

`state.md` 是当前工作的恢复入口，不是追加日志。目标 **≤80 个物理行（含标题与空行）**，并沿用活动摘要 ≤600 tokens 的预算；不拼成长行绕过限制。既有治理使用其映射的活动摘要字段，不另造一份可写状态。

- **每次更新前**按主题替换旧摘要；节点转换时移出已结束节点、已解除阻塞、已失效授权和不再支持当前动作的证据。新证据先登记最小回执，随后可把详情归档；禁止把完整命令输出、历次测试成绩、聊天过程或整段规格持续追加到状态。
- **保留当前必需项**：一个活动节点与完成门、有效授权的动作/边界/来源、相关最新证据结论与精确引用、未决风险/决断及解除条件、唯一下一动作。稳定规则/命令/Resolver 留在既有规则源或 overlay；规格、计划和 PROJECTMAP 不接管实时状态。
- **候选超限即收敛**：把历史按日期/主题追加到 overlay 指定的既有过程记录或证据报告，保留来源、核对时间和结论限制；状态只留当前摘要与 `路径#锚点` 或记录编号。先写归档并回读，再替换状态，最后复核引用、必要字段及行数。不新建 `state-2.md` 分担当前状态。
- **失败不丢数据**：归档不可写、来源无法回溯或现存状态已被其他写入方修改时，保留原文，先恢复记录/写入条件；必要授权或风险仍超限时保留它们，在状态注明原因和恢复动作，不截断、不把超限称为检查通过。只有新的权限/决策/证据障碍才暂停依赖动作。

行数用当前可用工具检查，例如 PowerShell `@(Get-Content -LiteralPath '<唯一状态路径>').Count`，或 Python `len(text.splitlines())`。每次写后核查；节点转换的过程回执记录行数及归档位置，普通更新不为此再写一串日志。80 行是体量判据，不是 token 节省或正确性的证明。

新源证据到达（用户截图、原件、人工决定、外部结果）时，**先于分析、设计请求或任何副作用**写最小证据回执：`received_at`、`source_ref`（不可持久保存则写 `needs-source`）、范围、直接观察、已知限制与当前未决。证据回执不等同于方案批准；没有来源不得把推断写成事实。只有项目或用户授权时才把原件复制到证据槽并记录可复核位置。

进入新会话或新活动节点时，如将复用既有用户或外部证据，先检查其回执是否有 `source_ref` 或 `needs-source`；缺失时先补录，再据此实施、部署或写入外部状态。

阶段顺序：

```text
reality_audit
  -> requirements
  -> tool_research
  -> solution_decision
  -> design_and_plan
  -> environment_and_authority
  -> repository_integration
  -> tdd_nodes
  -> real_evidence
  -> release_or_handoff
```

每次转换：

1. 按下述规约检查核对当前节点，再用新证据验证当前门。
2. 更新覆盖层解析的唯一活动状态，每个已声明作用域只保留一个活动节点。
3. 提交前同步本次事实涉及的规格、计划、规则、经验、Resolver、README 和对照语言版本。
4. 提交前把本次的发现、错误细节、改进目的、方案与选择、支撑数据追加到过程记录（路径见项目覆盖层）；无新增内容时写明本次无新发现，不留空。
5. 本地提交已获授权时，提交最小完整变更。
6. 下一动作仍在范围内且无停止条件时继续。

改变事实后，用旧说法全仓检索并处理每个命中。文档更新是检查点，不是停止点；交接只写一次性上下文，不承载可现查的分支、远端或身份事实。

强规则必须以**外部可观测事件**为**触发**，并写明**动作**、可复制方法、成功**判据**、**失败**处理和登记**证据**。内部判断不是稳定触发点。升级条件使用事件计数。

完成前 `IDENTIFY -> RUN -> READ -> VERIFY -> THEN`：目标、真实证据、回归、状态与文档、安装与版本控制、回滚和限制均须符合现实，且无必要工作未完成。

启动长测试、独立审阅或门控动作前，先保留足以读取结果、更新状态和启动下一门的运行余量。余量不足或不可确认时，先写可恢复交接：活动发现/证据、已完成验证、冻结的副作用、唯一恢复动作和解除条件；额度耗尽后不得视为完成，下一会话先恢复并重审。

<a id="project-conformance"></a>
## 项目规约检查

这是执行中的检查，不创建后台监控、第二份清单或周期性重读。普通动作复用已读规则；下列事件才展开对应原文和证据。

| 触发 | 动作与方法 | 通过判据 |
|---|---|---|
| 选定动作、进入节点或切换工作面 | 从覆盖层解析规则和状态；按地图定位当前范围、规则条款、授权及验收标准，核对计划项和拟改路径 | 动作与目标、规约及授权一致；当前作用域只有一个状态写入方；未跨阶段验收门 |
| 用户更正规约，或规则/overlay/地图/路径发生变化、引用失效 | 对照变更与来源版本，完整重读受影响条款，核对同一事项的唯一来源；入口变化后检查链接/锚点 | 冲突和失效入口已修复，计划及当前动作按有效规则调整；不以旧回执替代新证据 |
| 验证失败、节点转换或完成声明 | 用当前验收标准检查实际差异、具体结果、状态及相关文档；文档变更查引用与一致性，可执行路径变更查测试名称集合、跳过项及运行结果 | 证据覆盖当前版本和规则；状态及时更新；规格、计划及地图没有活动状态副本 |

发现偏离时，暂停受影响动作和门后的副作用；把偏离与唯一恢复动作写入活动状态。在已有范围和授权内修复、复验后继续，独立安全工作可继续；只有实质决策、新权限或必要证据缺失才按 [门控](gates.md) 请求用户。不把“检查到偏离”当完成，也不为规约对齐擅自迁移代码、合并分支或弱化验收。

节点转换、规则变化或发现偏离时，在既有过程记录留下最小回执：时间、规则来源及版本/核对时间、动作/范围、方法、结果、限制和恢复动作；活动状态只保留当前结论与证据指针。未变化的普通动作无需机械追加。地图只在入口、职责或读取触发变化时更新。规则靠 Agent 执行，确定性阻断仍由宿主权限与真实执行入口承担。
