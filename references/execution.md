# 节点执行参考

先读[公共合同](#common-contract)，再读当前节点小节；普通启动只读 [核心](core.md)。文档收敛按独立合同，仅在触发时展开。

## reality_audit：从现实开始

读取仓库规则、覆盖层启动摘要及其解析的唯一活动状态、Git 状态；用项目地图定位当前节点所需的规格、计划、实现、测试和运行证据，按章节/编号读取，不把链接清单当全文必读。区分已设计、实现、测试、部署和验收；明确目标、非目标、成功证据、约束、风险、授权边界、活动节点及下一门。旧消息、路线图勾选和模拟结果不能单独证明当前实现。

收到截图、原件、人工决定或外部结果时，先写最小证据回执，再分析或提出设计：记录接收时间、可复核来源（否则 `needs-source`）、范围、直接观察、限制和未决。该回执只冻结事实，不表示已经批准方案，也不授权副作用。

新会话或新活动节点复用旧证据前，检查既有回执是否含 `source_ref` 或 `needs-source`；缺失时先补录，不能直接作为实施、部署或外部写入依据。

项目需要本地规则、长期经验或 Resolver 时使用 [项目覆盖层模板](../assets/project-overlay.template.md)。覆盖层保存稳定项目事实；唯一活动状态保存易变内容。首次接入或治理缺口按 [初始化](project-initialization.md) 做现状映射与对齐，不从头重跑已完成阶段。

## requirements：厘清需求

确认用户结果、角色、敏感数据、隐私与权限、输入输出、规模、延迟、准确率、可靠性、离线、代表性样本、兼容性、部署、回滚，以及可逆 MVP 边界。一次只问一个真正阻塞的问题；安全假设不改变行为或风险时记录后继续。

## tool_research：调研当前工具

外部 spec、服务边界、功能或库/服务配置用法的问题先按[能力路由](capability-routing.md)调用 Context7；查询、缺失安装与降级沿用该处规则。

当库、模型、服务、Skill、协议、许可证或部署选项可能变化时，先查项目既有决定，再用一手资料核对版本、平台、许可证、安全、遥测、维护和部署要求。至少比较零新增基线、当前已有能力和需求足以证明合理的最强替代方案。

记录证据日期，区分事实与推断。自造分类、匹配、评分、相似度或阈值方法前先查成熟方案与公开基准；现成方案与自造方案都用同一批真实样本验证。只读联网研究可直接进行；安装、付费、外发数据和扩大权限另过授权门。

## solution_decision / design_and_plan：决策与计划

仅当选项实质改变行为、架构、持久数据、隐私、成本、许可证、部署风险或长期运行方式时请求用户决断。普通可逆细节采用满足验收的最简单方案。

记录选择、理由、淘汰方案、假设、风险、回滚和重审条件。实施节点写明文件、RED 测试、目标、验证命令、依赖、估时和停止门。强规则必须锚定外部可观测事件，写全触发、动作、执行方法、判据、失败处理和证据；升级条件使用可观测事件计数。

期望值来自已接受契约，并明确检查阶段：前置基线 B 表示允许开始的状态，后置目标 T 表示本批应达到的状态。
分别固定二者及来源，不静默重定义旧参数，也不因观察到偏差而改 expected 使其通过；目标取本次固定产物与范围，不自动取仓库最新版本。

把证据登记、可逆本地实验、远端部署、外部持久写入以及导入/激活列为不同动作类别。用户说“先检查并反馈”时，先交付检查结果；该条件性授权不覆盖实现或副作用。预实验单列目的、未覆盖验收、回滚与禁止推导结论，不能用“已部署”代替已批准设计的实现证据。

## environment_and_authority：环境与授权

先做只读检查，记录系统、运行时、依赖、网络、存储、服务、凭据边界、仓库结构、无关改动和验证命令。优先复用现有组件；第三方软件先查来源、许可证、遥测、安装脚本和安全影响。

授权请求说明动作、目标、持久性、外部影响和回滚。预授权工具集只免除集合内逐次询问，不免除适配检查、安装后验证和登记。

本地 RED/GREEN 或已写出的计划不自动授权远端复制、服务重启、外部持久数据写入、导入或激活。任何此类副作用均按其自身动作类别核对明确授权；模糊或条件性措辞按未获授权处理。

## repository_integration：集成仓库

- 保留无关改动，只增加目标所需内容；验证安装与回滚。
- 不提交秘密、个人信息或机器专属路径。可能接触凭据的命令先遮蔽值，**值不进上下文**；诊断结果**默认不落盘**，归档前脱敏。已泄露时不重复值，登记轮换、残留清理和暴露面。
- 输入输出目录派生自项目根或证据槽；绝对路径由参数注入并在覆盖层登记。
- 提交前读取实际暂存清单，提交说明覆盖全部文件；运行秘密扫描、通用性检查和身份检查；提交前运行[机械预检](gates.md#mechanical-preflight)（脚本见 [preflight.md](preflight.md)），block 失败不暂存、不提交。
- 创建、改写或引入提交后，按[提交对象回读](gates.md#commit-object-readback)核验实际结果，再继续依赖它的动作。
- 交付路径与仅开发路径分开；交付物依赖按交付边界判断。缓存和索引默认可重建。

## tdd_nodes：逐节点 TDD

对每个行为执行：写最小测试；确认预期 RED；做最小实现；确认聚焦 GREEN；仅在 GREEN 后重构；按风险跑回归与真实产物；修根因而不削弱测试；提交前同步状态和对照文档并运行[机械预检](gates.md#mechanical-preflight)；获授权时提交并激活下一节点。

## real_evidence：验证真实证据

完成声明前执行 `IDENTIFY -> RUN -> READ -> VERIFY -> THEN`，记录命令、退出码、测试数、产物或观察和限制。单元测试不能替代需求指定的真实样本、设备、浏览器、数据集、账号、外部服务、类生产负载或用户验收。

独立审阅发现 Critical/Important 问题时，把问题设为活动节点，复现、最小修复并重审；除非确有新决策、权限或证据阻塞，否则不得在该发现处结束本轮。不能继续时按门控写出停止理由和解除条件。

最后一次独立审阅后的代码、运行配置或交付包变更会使旧审阅失效；部署、发布或完成声明前必须审阅最终产物，测试、扫描、自审和旧版本现场验证不能替代。

证据产物登记位置、可达方式、处理过程、结论、边界和复核日期。默认槽：`.delivery/uploads/`、`artifacts/`、`debug/`。声明证据缺失前，先说明当前机器、目录、网络和权限的可达边界，不把不可达当成不存在。

<a id="resource-storage"></a>
## 资源归档：demo 与测试材料

生成或接收资料、选用测试素材、交付或清理时读取本节。按用途和保留期分类，图片、文档、语音、视频与 demo 源码使用同一规则；不按扩展名预建目录。优先复用项目已声明位置，否则使用现有任务编号（无编号用日期＋主题），在 `.delivery/artifacts/<task>/` 按需建立：

| 用途 | 位置 | 保留规则 |
|---|---|---|
| 中间文件、一次性测试输入/输出、可重建预览 | `tmp/` | 登记清理条件；任务完成不自动触发删除 |
| 需交付或长期复核的 demo、媒体、人工测试样本及结果 | `retained/` | 持续保留，受项目明确的到期/废弃决定约束；不得按临时目录清理 |
| 正式回归、构建或运行所依赖的资源 | 项目既有测试/fixture、组件或资源目录 | 随调用方维护；大型或受限文件用获准存储及可验证取回入口，不能只依赖忽略的本机目录 |

`uploads/` 仍接收获准的短期原件，`debug/` 仍存脱敏诊断；需长期保存时按上表处理。原件保持不改，裁剪、转码、脱敏与合成结果另存并标明派生关系。旧材料未标注保留期时先保留，不批量搬迁或推定可删除。

- **写入前**确定项目内目标、用途和保留期，核对目标及父路径的权限与链接/重解析点边界；用户请求交付或需不可重建的验收证据时选 `retained/`，只有明确可丢弃/可重建的中间物选 `tmp/`。类型不明先保留并登记待分类，不因目录名或扩展名丢弃。复用既有证据登记；没有时在任务目录放一份短 `README.md`，按[文档归属](context-lifecycle.md#ownership)只保留目录用途、最后批次、保留与恢复入口。相对路径、用途/用例、来源/版本、限制、校验与恢复明细写该批次清单；实测结果链接唯一证据，不在 README 累加所有文件和历次结果。测试样本关联用例和预期结果来源，不能编造预期或把合成样本标成真实证据。清单只在使用时读，状态和 PROJECTMAP 只留入口。
- **工具仅能写沙盒时**，在交付、任务结束或环境释放前，用获准方式把可取回文件和相对依赖复制到目标；不以沙盒、系统临时目录或工具缓存作为唯一交付位置。以大小与 SHA-256（例如 `Get-FileHash -Algorithm SHA256`）判定是否同内容：相同则直接复用，不同则不覆盖、另存并登记。逐文件比对后，再从项目目标打开/渲染/解码或运行相关测试，核验文档页、图片、音视频及 demo 的依赖可用；哈希相同不等于内容有效。记录源→目标、方法、结果和限制，最终链接指向已验证目标。传输不可达、权限不足、内容/依赖或校验失败时保留源，登记恢复动作，不宣称归档完成，也不清理源。
- **长期保留**同时登记项目既有备份/恢复入口并核验可达性；没有可验证恢复副本时标明“仅本地保存，恢复未验证”。`retained/` 延续 `artifacts/*` 的默认 Git 忽略，不自动提交、发布或随 Skill/软件包分发；忽略也不阻止文件同步。敏感原件按获准受限存储和数据规则处理，普通槽不是秘密保险箱。
- **成为正式依赖时**先复制并验证目标，更新调用方、测试发现/打包路径和资源索引，运行相关测试；大文件用项目已有存储方案及清单中的版本/哈希验证。完成迁移前保留可恢复原件，后续以目标为唯一维护来源，不长期双写。
- **清理时**先列明拟删路径、登记的条件和现存引用；只有条件已满足、无必要引用且删除授权已覆盖的临时项才可删除。`retained/`、未知材料和原件不纳入临时批量清理。逐路径核对解析目标与链接/重解析点，无法证明在获准范围就暂停该路径；不递归清空整个 `.delivery`。保留项变更期限/删除须有项目决定，按既有授权执行，不靠过期时间自动扩大权限。

<a id="common-contract"></a>
## 公共合同：状态与转换


默认存放根是 `.delivery/`。`state.md` 是活动状态的唯一事实源；采用既有治理时，每次读写先解析覆盖层的唯一指针，不再写默认路径。默认进入版本控制，明确的隐私偏离或已有治理状态适配按项目初始化合同登记；只写当前节点、有效授权、当前门、未决/在途事项与恢复。稳定项目事实、命令、规则和 Resolver 写项目覆盖层；实测与经验使用 overlay 指向的唯一证据和 lessons 来源；仓库未声明其他规则文档路径时，默认使用 `.delivery/overlay.md`，不得把全局记忆或 Skill 源仓库当作其替代。若项目隐私规则要求忽略该覆盖层，在唯一状态只登记其路径、范围和限制，不写敏感值。`uploads/`、`artifacts/`、`debug/` 默认忽略，不自动随软件包分发；产物和测试材料按 [资源归档](#resource-storage) 区分临时与保留项，用户交付提供核验后的资源链接。长期规格、正式证据报告和测试依赖按 [内容归属](project-initialization.md#project-map) 存放。只有采用默认布局的首次接入才复制完整的 [`.delivery` 骨架](../assets/delivery-skeleton.template.md)；项目可在覆盖层改存放根并登记偏离。

分支、HEAD、工作树、远端、身份、安装清单等**可现查事实**不得作为无时限的当前断言。需要登记时写成证据回执，包含验证时间、判据命令或解析器、适用范围和限制；后续会话引用前必须重新探测，事实漂移后立即更新活动状态。历史回执保留其 `as_of` 语义，不冒充当前现实。

<a id="state-size"></a>
### 状态与文档收敛

每次更新替换当前摘要。节点结束、交接、接入长文档、候选超预算或重复事实时，按[文档生命周期](context-lifecycle.md)检查 state、过程索引、证据摘要、产物 README 及其唯一来源。保留本锚点兼容旧入口；整理的归属、顺序、授权连续性与恢复规则只在该合同维护。

state 的软目标为≤80物理行、尽量≤5 KiB，活动摘要 token 预算另见[运行时合同](runtime-installation.md#context-budget)。已完成历史进入不可变批次记录，process 保留短索引；原文校验后才替换，不把历史从 state 转移成另一份无限追加的启动文件。必要授权、未知结果、未决风险、在途任务与恢复入口优先于体量目标。

新源证据到达（用户截图、原件、人工决定、外部结果）时，**先于分析、设计请求或任何副作用**写最小证据回执：`received_at`、`source_ref`（不可持久保存则写 `needs-source`）、范围、直接观察、已知限制与当前未决。证据回执不等同于方案批准；没有来源不得把推断写成事实。只有项目或用户授权时才把原件复制到证据槽并记录可复核位置。

进入新会话或新活动节点时，如将复用既有用户或外部证据，先检查其回执是否有 `source_ref` 或 `needs-source`；缺失时先补录，再据此实施、部署或写入外部状态。

阶段顺序：

```text
reality_audit
  -> requirements
  -> tool_research
  -> solution_decision
  -> design_and_plan
  -> environment_and_authority
  -> repository_integration
  -> tdd_nodes
  -> real_evidence
  -> release_or_handoff
```

每次转换：

1. 按下述规约检查核对当前节点，再用新证据验证当前门。
2. 更新覆盖层解析的唯一活动状态，每个已声明作用域只保留一个活动节点。
3. 提交前同步本次事实涉及的规格、计划、规则、经验、Resolver、README 和对照语言版本。
4. 提交前把影响后续工作的新增发现、决定、限制和证据记入既有记录体系；明细按批次保留，过程索引只更新必要入口，遵守[文档归属](context-lifecycle.md#ownership)。记录写入后按[落笔自检](gates.md#write-back-check)读回实际内容，与写入意图不符视为未完成。无新增事实就复用回执，不追加“无新发现”或重复测试过程。
5. 本地提交已获授权时，提交最小完整变更。
6. 下一动作仍在范围内且无停止条件时继续。

改变事实后，用旧说法全仓检索并处理每个命中。文档更新是检查点，不是停止点；交接只写一次性上下文，不承载可现查的分支、远端或身份事实。

强规则必须以**外部可观测事件**为**触发**，并写明**动作**、可复制方法、成功**判据**、**失败**处理和登记**证据**。内部判断不是稳定触发点。升级条件使用事件计数。

完成前 `IDENTIFY -> RUN -> READ -> VERIFY -> THEN`：目标、真实证据、回归、状态与文档、安装与版本控制、回滚和限制均须符合现实，且无必要工作未完成；完成与提交声明前运行[机械预检](gates.md#mechanical-preflight)并通过。

启动长测试、独立审阅或门控动作前，先保留足以读取结果、更新状态和启动下一门的运行余量。余量不足或不可确认时，先写可恢复交接：活动发现/证据、已完成验证、冻结的副作用、唯一恢复动作和解除条件；额度耗尽后不得视为完成，下一会话先恢复并重审。

<a id="project-conformance"></a>
## 项目规约检查

这是执行中的检查，不创建后台监控、第二份清单或周期性重读。普通动作复用已读规则；下列事件才展开对应原文和证据。

| 触发 | 动作与方法 | 通过判据 |
|---|---|---|
| 选定动作、进入节点或切换工作面 | 从覆盖层解析规则和状态；按地图定位当前范围、规则条款、授权及验收标准，核对计划项和拟改路径 | 动作与目标、规约及授权一致；当前作用域只有一个状态写入方；未跨阶段验收门 |
| 涉及正式记录的持久变更前，或本批验收/完成时 | 解析项目正式记录契约，按[一致性与完成门](gates.md#formal-record-consistency)核验对象、阶段、实际效果和记录 | 前置条件只允许开始；本批后置条件及记录义务通过才关闭完成门，已知欠账不作默认放行 |
| 用户更正规约，或规则/overlay/地图/路径发生变化、引用失效 | 对照变更与来源版本，完整重读受影响条款，核对同一事项的唯一来源；入口变化后检查链接/锚点 | 冲突和失效入口已修复，计划及当前动作按有效规则调整；不以旧回执替代新证据 |
| 验证失败、节点转换或完成声明 | 用当前验收标准检查实际差异、具体结果、状态及相关文档；文档变更查引用与一致性，可执行路径变更查测试名称集合、跳过项及运行结果 | 证据覆盖当前版本和规则；状态及时更新；规格、计划及地图没有活动状态副本 |

发现偏离时，暂停受影响动作和门后的副作用；把偏离与唯一恢复动作写入活动状态。在已有范围和授权内修复、复验后继续，独立安全工作可继续；只有实质决策、新权限或必要证据缺失才按 [门控](gates.md) 请求用户。不把“检查到偏离”当完成，也不为规约对齐擅自迁移代码、合并分支或弱化验收。

节点转换、规则变化或发现偏离时，在既有记录体系留下最小批次回执，过程索引只保留入口（见[文档归属](context-lifecycle.md#ownership)）：时间、规则来源及版本/核对时间、动作/范围、方法、结果、限制和恢复动作；活动状态只保留当前结论与证据指针。未变化的普通动作无需机械追加。地图只在入口、职责或读取触发变化时更新。规则靠 Agent 执行，确定性阻断仍由宿主权限与真实执行入口承担。
